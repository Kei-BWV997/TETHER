# 手つなぎ実装リファレンス（ICO〜現代ゲーム）

TETHER設計のための調査メモ。ICOの手つなぎと、現代ゲームの手つなぎ/接触系IKの実装パターンをまとめ、Skyrim SE(TETHER)への写像を整理する。

調査日: 2026-08-09

---

## 1. ICO (2001) — 原典

### 設計意図（Fumito Ueda）
- 手つなぎは「キャラクター間の"直接的なコミュニケーション"」を作るための中核メカニクス。プレイヤーが外部からコマンドを出すAIではなく、"介入して物語を形作れる"感覚を狙った。
- Uedaの言明: 「Yordaの動きが"考えて動いている"ように見えなければ、連れ歩きはただの雑用になる」。→ **繋がりが"生きて見える"ことが感情価値の源泉**。TETHERの狙い（張り/緩みで生きて見える）と完全に一致する。

### ボタン仕様
- **R1ボタン**でYordaを呼ぶ／手を取る。隣に来た瞬間、自動で手を握る。
- 北米版=押すたびにトグル（握る/離す）。他地域版=**押し続けている間だけ握る**。
  - → TETHERのMCM「押す/押し続ける」を両対応にする方針の裏付け。ICO自身がリージョンで両方式を持っていた。
- 手を引いて移動中、コントローラが一定間隔で穏やかに振動 → 「繋がり」の触覚フィードバック。

### 歴史的位置づけ
- Guinness認定「フレンドリーNPCと手を繋げる最初のビデオゲーム」。

### 観察された挙動モデル（ユーザー解析 / 要検証だが設計採用）
ICOのプレイ映像から読み取れた**非対称モデル**:
- **引く側（プレイヤー/Ico）= 剛体エイム**: 左腕を肩から先まで真っ直ぐ固定（肘・手首は曲げない）。腕全体を相手（Yorda）の**腰の骨あたり**へ向けて真っ直ぐ伸ばす。腕が「取っ手/竿」のように振る舞う。
- **引かれる側（フォロワー/Yorda）= IK伸縮**: 距離に応じて腕が伸び縮みし、手の接続を維持する側はこちら。コンプライアンス（追従の柔らかさ）を担当。
- 手同士は座標が重なるとめり込むため、**単純な手-手直付けではなく、片方をオフセットした接続点**に繋ぐのが自然に見える（後述の写像で採用）。

この非対称性は TETHER の方向性（プレイヤー主導）とそのまま噛み合う。**「主導側=剛性/従属側=柔性」**を基本ルールにできる。

## 2. 現代ゲームの実装パターン（手つなぎ/接触系）

ICOの内部実装は非公開だが、現代の等価技術は下記に分解できる。

### (a) Two-Bone IK（腕の到達）
- root(肩)・mid(肘)・tip(手)の3トランスフォームに対し、**target**（手の目標位置）と**hint/pole**（肘の曲がる方向）を与えて解く定番。
- TETHERの**引かれる側フォロワーの腕**に使う。target=プレイヤー側の接続ノード、hint=肘を体の外側に逃がす方向。

### (b) Aim / Look-At Constraint（剛体エイム）
- 肘を曲げず、**肩から腕全体を目標方向へ回転**させる。ICOの引く側の挙動そのもの。
- TETHERの**引く側プレイヤーの腕**に使う。肩ノードの回転で腕を相手へ向ける。
- 注意: 完全剛体だと相対角が極端な時（急旋回・真横）に破綻。ICOはカメラと地形で悪い角度を避けていた。オープンワールドのSkyrimでは避けられないので、**エイムに角度クランプ（コーン制限）を入れ、コーン外では上体（spine）回転やわずかな肘の遊びで逃がす**必要がある（TETHER側の追加設計）。

### (c) Full-Body IK（全身分配）
- 両手/両足/頭など複数エフェクタを一つの拘束系として同時に解き、**spineが動きを各関節へ分配**して全身で自然に辻褄合わせ。
- 引く側の「腕を向けると上体も少し捻れる」自然さは、これで出せる。MVPでは過剰かもしれないが、剛体エイム破綻対策として部分導入の候補。

### (d) IK Rig（GDC / Ubisoft系）
- authoredポーズを実行時にプロシージャルに再ターゲット/変形する枠組み。「ポーズは作家が作る、適応は実行時」という分業モデル。
- → TETHERの分業（**手のグリップ・ポーズはユーザーが authoring、腕の到達/エイム/伸縮はプラグインが procedural**）の裏付け。

### (e) Motion Warping / Contextual Reach
- 移動アニメの根を保ちつつ、手先だけ目標へ「歪める(warp)」。段差や相対位置のズレを吸収。
- TETHERの「バニラ走りモーションを使いつつ手だけ繋ぐ」に相当。

### (f) 接続点ノード＋オフセット（めり込み回避）
- 2キャラの手を同一座標に置くと必ずめり込む。実務では**片方の手を"接続アンカー"に対しオフセット**して握らせる。
- 握って見せるには、両手に**authoredグリップ・ポーズ**（指の握り形）を仕込む。ズーム時の見栄えはここで決まる。

## 3. TETHER (Skyrim SE) への写像

### レイヤー対応
| TETHER層 | 採用技法 | 主体 |
|---|---|---|
| L0 基礎移動 | バニラfollow/navmesh（motion warpingの"根"担当） | ゲームAI |
| L1 牽引ナッジ | 速度/heading補正（上限付き。Leashの力モデルを借用） | プラグイン |
| L2 手IK | 引く側=Aim constraint(剛体) / 引かれる側=Two-Bone IK(伸縮) | プラグイン |
| L3 テンション | 距離→バネ・減衰で L1/L2 を変調 | プラグイン |
| L4 剥がれ防止 | 接続点は常に有効な座標を返す安全弁＋角度クランプ | プラグイン |
| 接続表現 | ノード代替＋オフセット＋authoredグリップ・ポーズ | ユーザー(ポーズ)＋プラグイン(オフセット) |

### 接続アンカー・ノード候補（Skyrim skeleton）
プレイヤー左手 ← フォロワー右手[RHnd] を繋ぐ。**フォロワーの右手ボーンを、プレイヤー側の"手の代わりになるノード"へオフセット付きで追従**させる案。候補ノード:
- `AnimObjectL` — 手に追従する装備品用ノード。手のすぐ近くで、オフセットの基準に使いやすい。有力候補。
- `NPC L MagicNode` — 左手掌の魔法エフェクト用ノード。掌中心なので握り位置の基準に自然。
- `WEAPON` / `SHIELD` などの装備ノード — 装備物と競合しうるので優先度低。
- **カスタム・オフセットノード** — 上記いずれかの子として、めり込まない握り位置に定数オフセットで置いた自前ノードが最も制御しやすい（推奨方向）。

> 重要: 「手-手直付け」ではなく「フォロワー右手 → プレイヤー左手系のオフセットノード」。プレイヤー側の手ポーズとフォロワー側の手ポーズを、そのオフセットを前提に authoring して、握って見えかつめり込まないようにする。

### 非対称モデルの採用
- 引く側（プレイヤー）: 肩起点の**Aim constraint**で腕をフォロワーへ向ける剛体腕。角度クランプ必須。
- 引かれる側（フォロワー）: **Two-Bone IK**で接続ノードへ到達、距離で伸縮＝テンションの見え方を担う。

## 4. 未解決の技術リスク / 次に詰める点
- **剛体エイムの角度破綻**: 急旋回・真横・段差での肩エイム限界。クランプ＋上体回転で逃がす設計が要る。
- **接続点の座標保証(L4)**: フォロワーがnavで一時的に大きく離れた/障害物裏に回った時、接続ノードが不正座標を返さない安全弁。
- **手ポーズと武器/装備の競合**: 抜刀・松明・魔法構えとの排他制御。
- **一人称/三人称の差**: MVPは三人称前提でよいか（要確認）。
- **procedural と authored の境界**: 腕はprocedural、手グリップはauthoredで確定してよいか（次の設計質問）。
