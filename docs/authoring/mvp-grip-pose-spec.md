# 握りポーズ authoring 仕様書（将来: walk/デート段）

> **⚠️ スコープ注記（重要）**
> **run MVP では、この authoring は不要。** MVPは「プラグインが2つの手をいい感じに重ねるだけ／指はバニラ移動のまま」で握って見える、に簡約された（指先を凝視するのはゆっくり歩く時だけ、という判断）。
> 本書は **将来の walk/デートモード**（低速・至近・指先まで見える）で、握りをアート的に作り込む段のための資料として保持する。MVPでユーザーが作る成果物は無い。

対象: アニメーター（あなた）。この文書は **握りを作り込む段の成果物・作り方・書き出し** を定義する。
関連設計: 握り=C（軽い手つなぎ）／プレイヤー左手⇔フォロワー右手／WYSIWYG（オフセットの真実源は authoredポーズ）。

## 0. まず「あなたが作る範囲」と「プラグインがやる範囲」

| 部位 | 誰が動かすか | 備考 |
|---|---|---|
| フォロワー右腕 **肩〜手首の"配置と向き"** | **プラグイン**(2ボーンIK) | あなたは触らない。距離で肘が伸縮＝張りもプラグイン |

## 1. 最終成果物（MVP）

**Blenderシーン 1つ**：プレイヤー左手 と フォロワー右手 を、握りC のクラスプ配置でポーズしたもの。
そこから次の3つを取り出す（エクスポータは Claude が用意する。§5）：

1. **オフセット定数** = `RHnd` を `LHnd` のローカル座標で見た **位置＋回転**（＝2つの手の相対配置。これがWYSIWYGの真実源）
2. **プレイヤー左手 指ポーズ** = 左手の各指ボーンのローカル回転
3. **フォロワー右手 指ポーズ** = 右手の各指ボーンのローカル回転

**これだけ。** ロコモも、腕振りも、reachモーションも、MVPでは不要。

## 2. リグ（超重要）

- **ゲームで使う実スケルトン（XPMSSE等、あなたの環境と同一）でポーズする。** ボーン名・階層・bindが1:1で一致していないと、書き出したローカル回転がゲームでズレる。
- 別リグ（Mixamo等）で作らない。TETHERはボーン名 `NPC L/R Finger…` を直接読む。

## 3. 触るボーン一覧

### 指（あなたが authoring する）
親指/人差し/中/薬/小 の3節ずつ。左右とも同型。
```
左手: NPC L Finger00,01,02  (親指) / Finger10,11,12 (人差) / 20,21,22 (中) / 30,31,32 (薬) / 40,41,42 (小)
右手: NPC R Finger00,01,02  … 同上 …                                   NPC R Finger40,41,42
```
必要なら手首の微ロール（`NPC L/R Hand [LHnd]/[RHnd]`）も含めてよいが、**手首の"向き"は基本オフセット(回転)で担う**ので、指は指に集中。

### 腕（あなたは触らない＝プラグイン担当。参考まで）
```
NPC L/R Clavicle → UpperArm → Forearm → Hand [LHnd]/[RHnd]
```

## 4. 握りC の アートディレクション

狙い：**手のひらを軽く合わせて包む。指は絡めない（interlaceしない）。** ズームで「ちゃんと握ってる」に見え、かつ**めり込まない**こと。

- 2つの手のひらを**軽く重ねる／添える**。強く握り込まない（緊張しすぎない自然な握り）。
- **指は相手の指の"隙間に差し込まない"**（=Cの定義。交差はクリップ地獄なので将来のBで扱う）。指先は相手の手の甲/側面に軽く触れる程度。
- **わざと数mmの余裕**を持たせる（プラグインのIK誤差やオフセット微差を吸収）。ピッタリ0距離で密着させない。
- 想定カメラ：三人称の背後〜やや寄り。真横ズームでも破綻しない範囲で。
- 相対配置の目安：フォロワーは後方＋わずか左にいて、**プレイヤー左手が前方、フォロワー右手が後方から前へ**添えられる。左右の手のひらが向かい合う自然な角度で。

> ポイント：ここで作った**2つの手の相対配置（位置＋向き）がそのままオフセット定数**になる。だから「ゲームでこう握ってほしい」を、このシーンで完成形として作り込む＝WYSIWYG。

## 5. 書き出し（オフセット＆指ポーズの取り出し）

### 方法（推奨）: Claude製 Blenderエクスポータ
- あなたが§4のポーズを作ったら、**Blender用の小さなPythonスクリプト**を走らせるだけで、下記JSONを吐く。Claudeが用意する。
```json
{
  "offset": { "pos": [x,y,z], "rot_quat": [w,x,y,z] },   // RHnd rel LHnd
  "player_left_fingers":  { "NPC L Finger00": [w,x,y,z], ... },
  "follower_right_fingers": { "NPC R Finger00": [w,x,y,z], ... }
}
```
- 単位・座標系（Skyrim units / 軸変換）はスクリプト側で吸収する。あなたは**ポーズを作るだけ**。

### オフセットの数学（参考）
`offset = inverse(LHnd_world) * RHnd_world`（位置＋回転）。プラグインは実行時 `RHnd_target = LHnd_world * offset` で握り点を復元する。

### 実機ズレの保険
Blenderのbindとゲーム実行時ポーズは、まれに微差が出る（体重・スケール等）。もし実機でズレたら、**スライダーで数値を弄る（＝WYSIWYG崩壊）のではなく**、プラグインに「実機の LHnd/RHnd 実測値をログして真値をbakeする"calibrationキャプチャ"」を仕込んで、**実機の真実でオフセットを焼き直す**。Blenderは"見た目の真実源"、実機キャプチャは"数値の真実源"、という二段構え。
